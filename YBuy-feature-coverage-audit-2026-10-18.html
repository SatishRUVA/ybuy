  • Highest priority: establish hosted state; verify webhook-to-booking amount/payment checks; prove RLS/session isolation; approve refund/deposit/payout rules; enable only gated journeys that have approved policy and end-to-end tests.

4. Disabled and forthcoming functionality

  • Bidding/auction: `/bidding` and `/auction/:id` are demo UI; `mock_bidding` defaults off. README and `tests/bidding-demo.spec.ts` state no remote write, reservation or payment.
  • Item requests: schema/RPCs exist, but `requests` is in `OUT_OF_SCOPE_ROUTES`, `SHOW_OUT_OF_SCOPE_PAGES` is false, and the `item_requests` flag seeds disabled. Page presence is not user access.
  • Protection/item passport/need-something: routes are explicitly out of scope and rendered through the Part 1 unavailable gate.
  • Insurance: flag exists but no workflow; Admin UI marks unavailable.
  • Promotions/wallet credits: UI and DB primitives are test-only; no production checkout discount/spend/award.
  • Refund execution: approval/receipt foundations exist, but the DB gate prohibits execution; webhook receipts do not execute refunds or mark payments refunded.
  • Deposits: included in booking total/exposure, with no separate hold/release.
  • Admin reports/exports: overview exists; broad reports/CSV modules are forthcoming.
  • Email/push/SMS: no provider delivery flow found; in-app records exist.
  • Provider sample mismatch: `.env.example` recommends `google,facebook,apple`; config enables Google and disables Facebook/Apple, so copied env may reveal nonfunctional buttons.

5. Missing and incomplete implementation

Frontend / UI

  • Several routes are intentionally unavailable; item-request route access conflicts with meaningful database implementation.
  • Admin insurance and report/export capabilities are placeholders. Claims/support/wallet screens must not imply money resolution.
  • Accessibility checks are targeted, not a full keyboard/screen-reader/contrast/reflow audit.

Backend / database

  • Core/admin/operations schemas exist as migrations; hosted state is unverified and local Supabase API at 54321 was unavailable.
  • Deposit authorization/release and actual payout transfers are absent; payout rows are records, not proof of money movement.
  • Notification delivery provider, retry queue and delivery contract are absent.

Security / authorization

  • RLS and definer-RPC checks are present in source. Existing tests are SQL/local or mocked; remote policies, session revocation and storage isolation are unverified.
  • No repository evidence of security scan, pentest, marketplace-wide mutation rate limit, WAF/CSP policy or dependency/secret scanning.
  • Public profile column grants and private evidence rules are static findings only.

Business logic

  • Item request/negotiation paths are gated; expiration, visibility, eligibility and offer behavior need approved rules.
  • Either participant can advance pickup/return status; acceptance criteria for one- vs two-party evidence are unresolved.
  • Cancellation exists, but refund timing/allocation and post-payout liability are unresolved.

Financial workflows

  • Webhook confirmation should validate provider amount/currency/payment status against booking snapshot and handle duplicate/out-of-order events idempotently.
  • Refund execution is disabled; deposits lack hold/release; payouts are manual records without transfer verification.
  • Test promotion/credit primitives do not alter production checkout.

Notifications / integrations

  • Google OAuth, Maps/Places, Stripe, photo-analysis provider, Supabase Storage/Realtime and health-function runtime were not verified against live configuration.
  • No email/SMS/push delivery, retry queue or preferences were evidenced.

Testing

  • Playwright and SQL suites exist. This audit ran no tests/build/lint/typecheck. Browser/API tests use mocks and do not prove hosted RLS/OAuth/Stripe.
  • package.json has no test script; no coverage thresholds or CI workflow found.

Infrastructure / operations

  • Vercel SPA rewrite and CLI exist; no .github/workflows files were found.
  • No repository backup/restore evidence, RPO/RTO, restore drill, production alerting or incident runbook. Hosted backup controls are inaccessible here.

6. Business decisions and blockers

  • Refunds/cancellations: renter/owner/platform allocation, cancellation windows, post-payout responsibility, approval and execution authority.
  • Deposits: authorize vs charge, release timing, deductions, reconciliation and dispute linkage.
  • Disputes/claims: filing deadlines, evidence/retention, escalation, decision/appeal authority and financial outcomes.
  • Pickup/return: one- vs two-party confirmation, late-return handling and handoff evidence.
  • Item requests/negotiation: visibility, expiration, matching eligibility, offer expiry, max counter rounds and accepted-offer booking semantics. Database defaults are not business approval.
